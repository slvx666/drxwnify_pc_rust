## 2. Архитектурные правила соблюдения бюджета в Mini

### 2.1. Память (RAM Budget Rules)
1. **Виртуализация списков (Zero-Allocation Virtual Scrolling):**
   - Независимо от того, содержит ли медиатека 50 или 50 000 треков, в памяти интерфейса аллоцируются только те строки, которые физически помещаются на экране пользователя (`ScrollArea::show_rows`).
   - Никаких промежуточных списков-копий в каждом кадре: список передается по неизменяемой ссылке `&[Track]`.
2. **Кэш обложек (VRAM & RAM Caps):**
   - Размер текстурного кэша в GPU: жестко ограничен **50 текстурами** (`LruCache<String, TextureHandle>`).
   - При выходе обложки за пределы видимости текстуры вытесняются и деаллоцируются.
   - Декодирование картинок (`image::load_from_memory`) выполняется исключительно в пуле фоновых потоков `rayon` с предварительным даунскейлом до размера отображения (максимум `96×96px` для списка, `256×256px` для карточки альбома), что предотвращает загрузку гигантских 3000x3000px JPEG в оперативную память.
3. **Отсутствие дочерних процессов:**
   - Полный отказ от веб-рендереров Chromium/WebKit для Mini.
   - Один-единственный легковесный нативный Windows-процесс `DrxwnifyMini.exe`.

### 2.2. Процессор (CPU Budget Rules)
1. **Реактивный рендеринг (Reactive Event Loop):**
   - Никаких непрерывных 60 FPS таймеров при неподвижном интерфейсе.
   - Метод `ctx.request_repaint()` вызывается **только**:
     - При вводе с клавиатуры, движении мыши или скролле.
     - При получении аудиособытия смены миллисекунды (таймер с шагом 250 мс для ползунка прогресса).
     - При тике 32-полосного спектрографа (только если открыта правая панель или бар плеера, с частотой 20 Гц).
2. **Абсолютный ноль в покое:**
   - Если плеер на паузе или остановлен, приложение потребляет ровно **0.00% CPU**.
   - При сворачивании окна в трей или на панель задач отключаются любые запросы перерисовки.

### 2.3. Графика (GPU Budget Rules)
1. **Запрещенные операции в Mini:**
   - ❌ Никакого `backdrop-filter: blur()`, Гауссова размытия или свертки по текстурам.
   - ❌ Никаких многослойных полупрозрачных поверхностей (alpha compositing depth $\le 2$).
   - ❌ Никаких больших динамических теней (`box-shadow` с радиусом размытия > 0).
   - ❌ Никаких непрерывно анимирующихся процедурных фонов.
2. **Разрешенные операции:**
   - Плоские сплошные заливки поверхностей.
   - Четкие 1px контрастные рамки.
   - Мгновенные переходы состояний кнопок (hover/active) на основе смены цвета.
   - Статичная пиксельная или терминальная графика.

## 3. Методика измерений и протокол валидации

Для каждого релиза и сборки производятся аппаратные замеры с использованием официальных счетчиков Windows Performance Counters (PDH / Sysinfo):

1. **`WorkingSetSize`** — физическая память процесса, отображаемая в Диспетчере задач.
2. **`PrivateUsage`** — выделенная память, не разделяемая с другими библиотеками (Private Bytes).
3. **`% Processor Time`** — точный процент времени ядер CPU, измеренный за 30-секундный интервал.
4. **`LaunchTime`** — время от создания процесса в Windows (`Process::Create`) до появления первого отрисованного кадра окна (`SwapBuffers`).

Все измерения вносятся в `PERFORMANCE_RESULTS.md`. Любое превышение лимитов блокирует релиз.
