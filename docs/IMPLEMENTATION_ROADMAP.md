## 2. Поэтапный план реализации

### Этап 1: Инициализация Cargo Workspace и Drxwnify Core
- **Задачи:**
  1. Создание каталога `Drxwnify/rust-rewrite/`.
  2. Инициализация workspace `Cargo.toml` со всеми крейтами (`drxwnify-core`, `drxwnify-audio`, `drxwnify-playback`, `drxwnify-resolver`, `drxwnify-sources`, `drxwnify-catalog`, `drxwnify-storage`, `drxwnify-lyrics`, `drxwnify-nostr`, `drxwnify-win32`, `drxwnify-app`).
  3. Реализация базовых типов данных (`Track`, `AlbumRef`, `ArtistRef`, `Collection`).
  4. Реализация путей к хранилищу `%APPDATA%\DrxwnifyRust\` (`Paths.rs`).
  5. Настройка логирования через `tracing` и `tracing-appender` (вывод в консоль и в файл `app.log`).
- **Критерии завершения:** `cargo check` проходит без ошибок; пути корректно разрешаются на Windows; лог пишется на диск.

### Этап 2: Каркас UI (Tauri 2.0), дизайн-токены и переключение 9 тем
- **Задачи:**
  1. Настройка Tauri 2.0 в `drxwnify-app` с кастомным безрамочным окном (`decorations: false`, `transparent: true`).
  2. Создание структуры трех панелей (TopBar, LeftPanel, CenterContent, RightPanel, PlayerBar).
  3. Перенос всех 18 палитр тем (9 тем $\times$ 2 ночной/дневной режимы) в типизированные CSS-токены.
  4. Реализация аппаратного DirectComposition размытия (`backdrop-filter: blur(28px)`) для панелей над фоном.
  5. Подключение 27 шрифтов из `src/main/resources/fonts/` через `@font-face`.
- **Критерии завершения:** Окно запускается без мерцания; темы переключаются мгновенно без перезагрузки; размытие панелей работает аппаратно.

### Этап 3: Процедурный графический движок (Canvas Backdrops & Occult Shaders)
- **Задачи:**
  1. Реализация изолированного холста Canvas 2D / WebGL на фоне окна с привязкой к `requestAnimationFrame`.
  2. Перенос математики 9 бэкдропов:
     - `Mist` (3 дрейфующих пятна)
     - `GlyphField` (сетка глифов, шум Перлина, реакция на мышь)
     - `SakuraNightSky` (ветка сакуры, 42 лепестка, луна с гало)
     - `StarAtlas` (вращающаяся небесная сетка, созвездия, метеоры)
     - `CozyRoom` (вязаный плед, гирлянда, частицы пыли)
     - `Ash` (ланцетные арки, вращающийся рунический круг с пентаграммой, тлеющие угли)
     - `Retro` (перспективная 3D-сетка горизонта, полосатое солнце)
     - `Depth` (лучи сквозь толщу воды, каустика, всплывающие пузыри)
     - `Gruvbox` / `Mono` (аскетичные монохромные поверхности).
  3. Реализация логики `AnimationGate`: остановка анимации при сворачивании окна (`document.hidden`).
- **Критерии завершения:** Все 9 анимаций визуально идентичны Compose-версии; при сворачивании окна нагрузка на CPU падает до 0.0%.

### Этап 4: Аудиодвижок, декодирование FFmpeg и вывод WASAPI
- **Задачи:**
  1. Интеграция `ffmpeg-next` (или FFI) с минимальной LGPL сборкой FFmpeg.
  2. Настройка демуксинга сетевых стримов (опции reconnect, сетевой тайм-аут 8 секунд, User-Agent).
  3. Реализация аудиоресемплера в 48 000 Гц, 16-бит Stereo PCM.
  4. Интеграция `cpal` с бэкендом Windows WASAPI (размер буфера ~200 мс).
  5. Реализация команд `play`, `pause`, `seek`, `stop`.
- **Критерии завершения:** Чистое воспроизведение локального файла и сетевого потока без щелчков, задержек и отставания звука.

### Этап 5: Аудио DSP (Громкость, Баланс, Нормализация, Срез тишины, FFT)
- **Задачи:**
  1. Формула перцептивной громкости: $\text{gain} = \text{volume}^{1.7} \times \text{fade}$.
  2. Стереобаланс каналов от -1.0 до +1.0.
  3. Скользящий фильтр среднеквадратичного значения (RMS) и динамическая нормализация.
  4. Детектор тишины (Lead-in отсечение тишины в начале и Tail обрезка тишины в конце трека).
  5. Интеграция `rustfft`, окно Ханна, 32 логарифмические полосы с эмиттом в UI на частоте 20 Гц.
- **Критерии завершения:** Тестовый трек с тишиной в начале стартует со звука; ползунки громкости и баланса работают в реальном времени; спектрограф визуализирует частоты.

### Этап 6: Аудиокэш, префетч и бесшовный Hot-Swap
- **Задачи:**
  1. Реализация модуля `drxwnify-storage::AudioCache` (сохранение потока в `%APPDATA%\DrxwnifyRust\cache\audio\`).
  2. Фоновая потоковая запись трека во временный `.part` файл.
  3. Атомарное переименование в `.audio` и создание метафайла `.json`.
  4. Метод `attach_local`: бесшовная подмена сетевого декодера на локальный файл на текущей миллисекунде.
  5. Интеграция демуксера `Remuxer` для конвертации потоков без пережатия (сохранение в `.opus`, `.m4a`, `.mp3`).
- **Критерии завершения:** Повторный запуск трека открывает локальную копию мгновенно; перемотка кэшированного трека занимает 0 мс.

### Этап 7: Сетевой стек и источник YouTube Music (InnerTube)
- **Задачи:**
  1. Реализация асинхронного клиента InnerTube на базе `reqwest`.
  2. Эмуляция клиентов VisionOS, Android VR 1.65, Android VR 1.43.
  3. Парсинг ответов `player`, извлечение адаптивных аудиопотоков (itag 251, 140, 250).
  4. Поиск треков по запросу (SongFilter) и сопоставление по длительности ($\pm 6$ секунд).
- **Критерии завершения:** Запрос трека возвращает валидный прямой URL потока Opus/AAC; трек успешно декодируется.

### Этап 8: Источник ВКонтакте (VK Music API 5.116 и HLS AES-128)
- **Задачи:**
  1. Реализация клиента API 5.116 с User-Agent официального клиента VK.
  2. Поддержка как персонального токена, так и общего демо-аккаунта с лимитом треков в день (`vk_shared.json`).
  3. Алгоритм нечеткого сопоставления (`likeness` $\ge 0.7$, артист $\ge 0.5$).
  4. Преобразование адресов `index.m3u8` в прямые MP3, либо дешифрование HLS через FFmpeg crypto.
- **Критерии завершения:** Трек из VK успешно воспроизводится с битрейтом 320 kbps; при исчерпании лимита происходит корректный fallback.

### Этап 9: Дополнительные источники (SoundCloud, Lossless, Bandcamp, Audius)
- **Задачи:**
  1. SoundCloud: скрапинг `client_id`, поиск по API, строгий 8-секундный фильтр длительности `ProviderGate`.
  2. Lossless: загрузка списка зеркал из RemoteConfig, валидация по ISRC, извлечение FLAC 1411 kbps.
  3. Bandcamp: поиск через autocomplete, извлечение MP3-128.
  4. Audius: ротация нод `api.audius.co`, получение открытых аудиопотоков.
- **Критерии завершения:** Все 4 источника возвращают валидные ссылки при наличии трека в их каталогах.

### Этап 10: Конкурентный резолвер потоков (Stream Racer)
- **Задачи:**
  1. Реализация конкурентной гонки `FuturesUnordered` в `drxwnify-resolver`.
  2. Динамический тайм-аут ожидания источников (700 мс для speed, 2000 мс для quality, 8000 мс для patient).
  3. Система приоритетов и ранжирования по битрейту.
  4. Система предложений апгрейда `SourceUpgrades` (зеленая стрелка в UI при запоздалом ответе с лучшим качеством).
  5. Диалог выбора версии вручную (`choose_version`).
- **Критерии завершения:** Трек начинает играть за минимальное время; при победе лучшего битрейта плеер переключается автоматически.

### Этап 11: Управление воспроизведением и очередью (Player State Machine)
- **Задачи:**
  1. Реализация очереди до 500 треков (`push`, `insert_next`, `remove`, `reorder`).
  2. Режимы перемешивания `Shuffle` (первый трек сохраняется) и повтора `RepeatMode` (Off, All, One).
  3. Бесконечная очередь (Radio): автоматическая подгрузка 25 треков при приближении к концу очереди.
  4. Таймер сна: линейное угасание звука за 20 секунд до конца интервала.
  5. Автосохранение очереди в `queue.json` с дебаунсом 3 секунды.
- **Критерии завершения:** Все сценарии очереди (переход, удаление, перемешивание, сохранение при рестарте) работают штатно.

### Этап 12: Модули каталогов и интеграция ссылок (Catalogs & AppLinks)
- **Задачи:**
  1. Каталог Spotify: парсинг альбомов, артистов, плейлистов, дискографий (GQL / Web API).
  2. Каталог Яндекс Музыки: чтение альбомов, треков, плейлистов (анонимно и по токену).
  3. Модуль `AppLinks`: генерация ссылок `drxwnify.pages.dev`, парсинг входящих ссылок Spotify, Яндекс, YouTube.
  4. Рекомендации главной страницы (`PersonalHome`) и жанровые фильтры (`Genres`).
- **Критерии завершения:** Вставка любой ссылки в строку поиска открывает соответствующую сущность.

### Этап 13: Медиатека, загрузки и локальное хранилище
- **Задачи:**
  1. Хранилище `Store<T>` с атомарной записью JSON (`library.json`, `settings.json`, `downloads.json`).
  2. Логика лайков (Liked Tracks) с отметками времени и синхронизацией со Spotify.
  3. Менеджер загрузок: скачивание треков, ремуксинг без перекодирования с внедрением тегов ID3/VorbisComment.
  4. Экспорт треков в локальные файлы.
- **Критерии завершения:** Файлы сохраняются в папку `Music/Drxwnify` с корректными тегами и обложками.

### Этап 14: Сервис синхронизированных текстов (Lyrics & Google Translate)
- **Задачи:**
  1. Каскадный опрос LRCLIB -> BetterLyrics -> KuGou.
  2. Парсинг формата LRC с микросекундными таймкодами.
  3. Пакетный перевод непереведенных строк через Google Translate API (пачками по 15 строк).
  4. UI текстов: плавная прокрутка, активная строка со свечением, переключатель перевода.
- **Критерии завершения:** Тексты подсвечиваются синхронно со звуком; перевод появляется под строками без задержек.

### Этап 15: Децентрализованный Nostr-чат (RelayPool & ChatHub)
- **Задачи:**
  1. Криптография Secp256k1, Schnorr сигнатуры (BIP-340), NIP-04 шифрование (AES-256-CBC).
  2. Пул WebSocket-соединений к 5 релеям (`damus`, `nos.lol`, `primal`, `nostr.mom`, `snort`).
  3. Подписка на личные сообщения (Kind 4), индикацию набора текста (Kind 21004) и статус прослушивания (Kind 30078).
  4. Поддержка 36 кастомных WebP стикеров и реакций.
  5. Функция «Слушать вместе» (синхронизация воспроизведения с другом).
- **Критерии завершения:** Сообщения шифруются и расшифровываются; стикеры отображаются; статус совместного прослушивания обновляется.

### Этап 16: Интеграции с Windows и Discord RPC
- **Задачи:**
  1. Discord Rich Presence через локальный Named Pipe `\\.\pipe\discord-ipc-0..9`.
  2. Глобальные горячие клавиши Windows API (`RegisterHotKey`) в фоновом потоке.
  3. Windows System Media Transport Controls (SMTC) через `windows::Media::Playback`.
  4. Настройка стилей окна (`WS_EX_APPWINDOW`, `AppUserModelID`) для правильного отображения в Диспетчере задач.
  5. Системный трей с контекстным меню.
  6. Контроль единственного экземпляра (TCP сокет `127.0.0.1:47833`).
- **Критерии завершения:** Статус трека отображается в Discord; мультимедиа-клавиши клавиатуры управляют звуком; второй запуск разворачивает окно.

### Этап 17: Импорт резервной копии Android (.backup)
- **Задачи:**
  1. Распаковка ZIP-архива `.backup`.
  2. Чтение базы Room `song.db` через `rusqlite` (таблицы `song`, `artist`, `album`, `playlist`, `history`).
  3. Парсинг SharedPreferences XML через `quick-xml`.
  4. Импорт учетных записей из Protobuf DataStore.
- **Критерии завершения:** Бэкап с телефона переносит всю медиатеку и историю в Rust-версию за один клик.

### Этап 18: Полировка 12 экранов, модальных окон и визуальных стилей
- **Задачи:**
  1. Завершение всех 12 экранов (Home, Search, Liked, Downloads, History, LocalPlaylist, RemotePlaylist, Album, Artist, Discography, Reviews, Friends).
  2. Реализация 8 стилей `Look` (Polybar в Terminal, золотые рамки в Atlas, готические арки в Rite, неоновые тени в Neon).
  3. Контекстные меню треков, модальные диалоги, CoverViewer (просмотр обложки на весь экран).
  4. Виртуализация длинных списков (TanStack Virtual) для стабильных 60 FPS при 10 000 треках.
- **Критерии завершения:** Интерфейс неотличим от оригинального скриншот к скриншоту; прокрутка списков абсолютно плавная.

### Этап 19: Профилирование, замеры производительности и упаковка MSI
- **Задачи:**
  1. Измерение потребления памяти в сценариях: старт, простой, активное воспроизведение, свернутое окно.
  2. Измерение нагрузки на CPU (цель: < 0.2% в простое).
  3. Сборка продакшн-релиза: `cargo build --release`, LTO, strip.
  4. Генерация самостоятельного установщика MSI через WiX Toolset.
- **Критерии завершения:** Установщик MSI весит < 18 МБ; потребление RAM в покое < 120 МБ; CPU в покое < 0.2%.
